# Видео и изображения

Рабочие файлы: public/media/algyr/platform. Заглушек нет.

## Видео

- media-source/camera-original.mp4 — предоставленный algyr_laptop_screen.mp4: 1280 × 720, 24fps, 10 секунд. Исходник сохранён.
- media-source/camera-prepared.mp4 — исправленный монтаж: нормализованный снимок 16:9 вписан в видимый дисплей по отдельным координатам каждого кадра. Первые 96 кадров сохраняют исходную сцену; замена плавно появляется в кадрах 96–100 после поворота ноутбука. Вертикального сжатия в конце нет. Повторяется scripts/composite-laptop.py из исходного ролика, shot-1.webp и координат media-source/screen-tracking.json.
- media-source/camera-enhanced-1080.mp4 — улучшенная копия: 1920 × 1080, 24fps, 240 кадров, 10 секунд, без звука, 10 163 807 байт. Обработка: hqdn3d 0.6:0.4:1.2:0.8, Lanczos, unsharp 0.38, H.264 CRF16, faststart. Утраченные исходные детали не реконструируются AI.
- frames/f_000.webp…f_119.webp — 120 кадров, 12fps, 1280 × 720, WebP quality85. Общий вес 4 741 922 байт. Последний кадр скопирован из shot-1.webp для точного стыка.
- poster.webp — первый кадр; poster-mobile.webp — обложка 720 × 405, 24 930 байт.

JS загружает сначала первый и последний кадры, затем каждый десятый и остальные, не более четырёх запросов одновременно. Сжатые кадры занимают около 4,74 МБ; в декодированном виде хранится до 10 кадров (примерно 37 МБ RGBA без учёта браузерных накладных расходов). При загрузке рисуется ближайший доступный кадр. При переключении варианта desktop/mobile старый набор освобождается; в статичном режиме декодированные кадры также освобождаются.

## Скриншоты

shot-1 — последний список «Менің курстарым» (исходник 1600 × 738).
shot-2…shot-6 — главная, урок, результаты, пробный тест, профиль из последних присланных материалов. Email профиля уже скрыт в сохранённом исходнике.

Все снимки вписаны в 1280 × 720 с сохранением пропорций, без обрезки. Свободное место заполнено цветом фона. На мобильном используются отдельные `shots-mobile/shot-1.webp … shot-6.webp`, вписанные в 720×405, и `frames-mobile/f_000.webp … f_119.webp`: 120 кадров, 2 001 236 байт. Максимум 6 декодированных кадров (~7 МБ RGBA). Финальный кадр байтово совпадает с мобильным shot-1. Скролл нативный, системного видеоплеера нет.

Старые неподвижные scene.webp/background.webp удалены из рабочих ассетов. Брендовый фиолетовый фон platform-bg.png и шрифты ALGYR сохранены.

## Повторный экспорт

Требуются Python + Pillow, OpenCV, NumPy и FFmpeg с libx264/libwebp только на машине сборки:

```sh
python scripts/track-laptop.py
python scripts/composite-laptop.py --ffmpeg /path/to/ffmpeg
python scripts/check-screen-tracking.py
python scripts/make-frames.py --ffmpeg /path/to/ffmpeg --enhance
python scripts/make-frames.py --ffmpeg /path/to/ffmpeg --verify-only
```

Без --enhance используется уже готовый Full HD master. Параметры --fps 12, --quality 85, --width 1280, --duration 10, --budget 6000000. Скрипт проверяет размеры, число и вес кадров, соответствие финального снимка, отсутствие аудио; пишет docs/MEDIA-REPORT.json. При смене FPS/числа кадров обновите sequence в PHP-конфиге. Ширина кадров должна совпадать с холстом скриншотов.

Для повторного экспорта шести снимков: scripts/build-platform-assets.py. После этого обновите подготовленное видео при смене shot-1 и снова запустите make-frames.py. Исходные файлы пользователя не перезаписываются.


Проверка конца зума: scripts/check-video-aspect.py измеряет первую оранжевую карточку в кадрах108–119. Её высота растёт с31 до39px, ширина — с137 до168px; сжатия по вертикали нет. Результат — video-aspect-check.json.

## Привязка к экрану

В screen-tracking.json сохранены 144 измеренных четырёхугольника (по одному на кадр при 24fps), FPS и SHA-256 исходника. До появления дисплея координаты null: наложение отключено. track-laptop.py выделяет весь дисплей, включая тёмное меню, вместо экстраполяции белой области по редким ключевым точкам. Детектор настроен на этот ролик; для другого нужна повторная калибровка.

composite-laptop.py ограничивает замену внутренней маской дисплея и проверяет отсутствие изменений вне неё до кодирования. check-screen-tracking.py сравнивает все 240 декодированных кадров с оригиналом вне экрана с допуском на H.264 и сохраняет контактные листы в output/tracking-review. Отчёты: screen-composite-check.json и screen-tracking-check.json.

Мобильные материалы: `python scripts/make-mobile-frames.py --ffmpeg /path/to/ffmpeg`. Готовая автономная копия всех нужных файлов — `standalone/algyr-block/`; пересборка: `php scripts/export-standalone.php`, затем `node scripts/build-standalone.mjs`.
